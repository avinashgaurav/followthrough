Why it's different

Meeting summarizers give you notes. Followthrough gives you a ledger of promises.

01 · Citation gate

No quote, no insight

Every extracted ask must carry a verbatim quote that is checked against the transcript in code. Hallucinated takeaways never reach your queue.

vs. "the client seemed interested in..."
02 · Human gate

The AI drafts, people decide

Nothing reaches a client without a person confirming it. No auto-sent emails, and no ticket is filed until a person clicks.

vs. bots that email your customers
03 · Event log

Every step is timestamped

An append-only log records each move, so you can measure how fast an ask travels from said to shipped to told, per client and per person.

vs. a summary you read once and lose

Use it from Claude or Cursor

Ask your AI assistant what you promised.

Followthrough is an MCP server with 26 tools. Make a token in Settings, paste one command, then ask Claude Code, Cursor or Claude Desktop: “What did we promise Acme?” or “Brief me for the Globex call.” Tokens only reach the tools, and you can revoke them any time.

# Settings → Connect an AI assistant (MCP) → Make a token
claude mcp add --transport http followthrough \
  https://followthrough-hosted.vercel.app/api/mcp \
  --header "Authorization: Bearer ftk_..."

Run your own

Your data lives in your own Postgres.

Deploys to Vercel with Supabase: Postgres for the data, Supabase Storage for files. Deepgram transcribes audio; transcript text goes to the AI key you bring: Gemini, Anthropic or OpenRouter.

# needs Bun 1.3+ and a Postgres URL
git clone https://github.com/avinashgaurav/followthrough.git
cd followthrough && bun install
echo 'DATABASE_URL=postgres://...' >> .env
echo 'GEMINI_API_KEY=...' >> .env
bun run build:web && bun run start   # http://localhost:4500
