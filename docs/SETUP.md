# Setup and development

Deploying, running locally, every environment variable, a public demo, and the development commands.

## Deploy on Vercel + Supabase (recommended)

Followthrough runs as one Vercel project: the web app is static output, `api/server.ts` serves every `/api/*` and `/share/*` request on Vercel's Bun runtime, and Postgres plus file storage come from Supabase.

1. **Create the project.** Import the repo in Vercel (Root Directory: the repo root). `vercel.json` sets the build, the function (300s limit) and a daily cron.
2. **Add Supabase.** In the project: Storage → Supabase (Vercel Marketplace). Vercel creates the database and adds `POSTGRES_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and the rest. Nothing to copy by hand.
3. **Set the environment variables** (Settings → Environment Variables):

   | Variable | Needed for |
   |---|---|
   | One AI key: `GEMINI_API_KEY`, `ANTHROPIC_API_KEY` or `OPENROUTER_API_KEY` | extraction, emails, Ask. With several keys, Anthropic wins unless `LLM_PROVIDER=gemini` |
   | `PRODUCT_NAME` (and optionally `PRODUCT_DESCRIPTION`) | framing every AI prompt |
   | `CRON_SECRET` (any long random string) | the daily cron; without it the cron route refuses to run |
   | `DEEPGRAM_API_KEY` | transcribing uploaded audio. Without it, paste transcripts instead |
   | `GITHUB_READ_TOKEN` + `RELEASE_REPO` | matching shipped releases to client asks |
   | `GITHUB_WRITE_TOKEN` + `WRITABLE_REPOS` | creating GitHub issues directly from a ticket draft |

4. **Deploy.** The production build runs `bun run db:migrate` (every migration is idempotent) and then builds the web app.
5. **Create the first admin.** On Vercel (and whenever `NODE_ENV=production`) login is always required and there is no guest access, so the first admin comes from the command line. From a local checkout linked to the project:

   ```bash
   vercel env pull .env.local --environment=production   # database settings, git-ignored
   bun run seed you@yourcompany.com "Your Name"          # or set ADMIN_EMAIL / ADMIN_NAME
   ```

   It prints a one-time login code; sign in with your email and that code. Add teammates from **Settings → Access**. Running it again for an existing email changes nothing (rotate a lost code from Settings). `OPEN_ACCESS=true` turns the open, no-login mode back on for a deployment; `DEMO_MODE` deployments stay open and read-only.

What changes on Vercel compared with a long-running server:

- **Uploads:** audio goes from the browser straight to a private Supabase Storage bucket (`followthrough`, created on first use with a size limit and an allowed-type list) through a signed URL, because Vercel caps request bodies at 4.5 MB. The server then checks the stored file's real size. **On Supabase's free plan a file can be at most 50 MB**, about an hour of compressed audio; longer calls need a paid plan or a pasted transcript. Downloads are short-lived signed URLs.
- **Transcription:** Deepgram fetches the recording itself from a signed URL. Local whisper.cpp is gone (functions cannot run native binaries).
- **Scheduled work:** one daily cron (`/api/cron/daily`, 03:30 UTC = 09:00 IST) runs the Monday digest, the release poll, the "waiting on the team" nudge and the stale sweeps. The Hobby plan allows one run a day, so releases are polled daily; Settings → Releases → **Check GitHub now** works any time.
- **Long requests:** transcript chunks are extracted 4 at a time (`EXTRACT_CONCURRENCY`). If extraction took over 2 minutes, the meeting brief is generated by a second request, which the app makes for you.
- **Counters:** the daily AI budget and the Ask rate limit are stored in the database, so they hold across function instances.
- **The watch folder is removed:** there is no local folder on Vercel. Upload transcripts on Capture.
- **Supabase's REST API is shut off for these tables:** migration 003 enables row-level security and revokes the `anon` and `authenticated` roles, because the app only ever connects as the database owner.

## Run it locally

**Prerequisites:** [Bun](https://bun.sh) 1.3+ and a Postgres database (a Supabase project, or any Postgres 15+).

```bash
git clone https://github.com/avinashgaurav/followthrough.git
cd followthrough
bun install

# .env is gitignored. With a Vercel project linked, `vercel env pull .env.local` fills in the database.
echo 'DATABASE_URL=postgres://...'   >> .env   # or POSTGRES_URL
echo 'GEMINI_API_KEY=...'            >> .env   # or ANTHROPIC_API_KEY / OPENROUTER_API_KEY
echo 'PRODUCT_NAME=Acme'             >> .env

bun run build:web
bun run start            # http://localhost:4500, applies migrations on startup
```

Without `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`, files are stored on disk under `BLOB_DIR` (default `./data/blobs`). `DB_SCHEMA=<name>` runs the app inside a separate Postgres schema, handy for a smoke test that must not touch the real tables. Locally the app is open (every visitor is a guest admin) until an admin turns **Require login** on in **Settings → Access**; `REQUIRE_LOGIN=true` forces it on. `bun run seed` creates a first admin as in step 5.

## Run a public demo

`DEMO_MODE=true` turns an instance into a read-only showcase, and `bun run seed:demo` fills an empty database with three fictional client meetings (Acme, Globex, Initech for a made-up product, Tallyhall) run through the real extraction pipeline, plus a changelog that ships two of the asks and a closed loop for one client. The Docker image runs the demo seed automatically on first boot when `DEMO_MODE` is on.

```bash
DEMO_MODE=true LLM_DAILY_BUDGET_USD=5 PRODUCT_NAME=Tallyhall bun run seed:demo && bun run start
```

Seeding makes real LLM calls once and is all-or-nothing (one transaction): a failure leaves the database untouched. It skips a database that already has meetings. Demo mode caps AI spend at $5/day unless `LLM_DAILY_BUDGET_USD` says otherwise.

The hosted demo linked from the README needs no server at all: `cd web && bun run build:demo` builds a static, read-only copy of the web app that serves responses recorded from a seeded `DEMO_MODE` instance and refuses every write. No model calls, nothing persists between visitors. How it works and how to re-record the fixtures: [`web/src/demo/README.md`](../web/src/demo/README.md).

## Development

```bash
bun run dev            # server with --watch
cd web && bun run dev  # vite dev server, proxies /api to :4500
bun test               # 349 tests (in-process Postgres via PGlite)
bunx tsc --noEmit      # typecheck
bun run evals          # extraction quality scoring (needs an LLM key)
```

CI (`.github/workflows/ci.yml`, on pushes to `main` and on pull requests) typechecks the server, web app and extension, runs the test suite, and builds the web app and extension. It does not run the LLM evals.

The full product contract lives in [`SPEC.md`](../SPEC.md). Design references are in [`design-reference/`](../design-reference/).
